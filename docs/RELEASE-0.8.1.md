# Сменник 0.8.1 — исправление совместимости установки

## Симптом
Пользователь сообщил, что выпуск 0.8.0 не устанавливается поверх более ранней версии.

## Что установлено по локальному анализу
- В 0.7.1 и 0.8.0: Android applicationId `ru.smennik.app`.
- Схема подписи v2 математически проверена обоих APK, SHA-256 сертификата совпадает.
- VersionCode повышается с 14 (0.7.1) до 15 (0.8.0). Для 0.8.1 увеличен до 16.
- Фактическую причину отказа установки установить без сообщения PackageInstaller/ADB и устройства нельзя.
- Ранее созданные экспериментальные APK с JAR/v1-подписью имели **невыровненные**
  несжатые нативные библиотеки `.so`; их не следует распространять.

## Профилактическое исправление установки
Подготовленный APK подписывается двумя схемами v1+v2 с сохранением исходного
постоянного сертификата. После операции JAR/v1 **и до APK/v2** нативные
библиотеки должны иметь смещения, кратные 16384 байтам, `resources.arsc`
кратные 4 байтам. Проверяется валидность JAR-подписи после ZIP-выравнивания,
APK-подписи v2 после финального подписания, CRC, manifest и fingerprint.

## Требования безопасности и совместимости
- Не менять package id и сертификат. Не включать приватные ключи в Git или релиз.
- Схема SQLite остаётся v7, JSON v8, удаление пользовательских данных не предусмотрено.
- Физическая установка на конкретном Android не подтверждена; при отказе нужен
  точный текст ошибки. Никогда не советовать удаление старой версии без JSON-копии.
- Если пользовательская текущая сборка подписана другим сертификатом, APK с
  постоянным release-сертификатом её поверх не заменит.
- Альтернативная техническая диагностика при наличии ADB:
  `adb install -r Smennik-0.8.1-signed.apk`.
  Для `INSTALL_FAILED_UPDATE_INCOMPATIBLE` проверить сертификат текущего пакета.
