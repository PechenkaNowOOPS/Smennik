# Android: восстановление устанавливаемости APK 0.8.0

## Обнаруженная проблема

Пользователь сообщил, что 0.8.0 не устанавливается поверх старой версии.

Сравнение исходных APK 0.7.1 и 0.8.0 показало:
- `applicationId=ru.smennik.app` в обоих случаях.
- `versionCode` увеличен 14 → 15.
- Контрольная цифровая подпись APK Signature Scheme v2 использует один и тот же
  сертификат SHA-256: `3396473c1ccd3a0c6ee483e098d1546bc759a2e92d01519f46930eedb4614b6f`.
- Исходный файл 0.8.0 имеет ZIP-выравнивание. **Причина первого отказа
  установки не подтверждена**: нет системной ошибки Android.
- Отдельно выявлен дефект у промежуточно переподписанного файла исправления:
  `jarsigner` пересобрал ZIP и нарушил 4-байтовое выравнивание 65
  несжатых файлов, включая библиотеки `.so`. Этот файл непригоден
  для безопасного выпуска.

## Исправленный установочный пакет

Файл `Smennik-0.8.0-install-fixed.apk` подготовлен локально из исходной
сборки 0.8.0: подпись v1, повторное корректное ZIP-выравнивание,
подпись v2. Никакие пользовательские данные или исходники программы в
этом перепаковывании не изменяются.

Проверено:
- `jarsigner -verify`: архив APK v1 подписан и проверен.
- Независимая проверка RSA подписи и digest APK v2 локальным анализатором:
  подпись проходит, сертификат тот же.
- Все несжатые ZIP записи выровнены по 4 байта; несжатые
  `lib/**/*.so` выровнены по 16 KiB.
- Контроль ZIP CRC ошибок не выявил.
- `package=ru.smennik.app`, `versionCode=15`, `versionName=0.8.0`.

**Важно:** на физическом телефоне установка ещё не протестирована.
Это корректирующий артефакт, а не доказанный диагноз первого отказа.

## Правильный процесс подписи следующих APK

Рекомендуемый вариант при наличии Android SDK Build Tools:

```sh
zipalign -P 16 -f 4 app-release-unsigned.apk app-aligned.apk
apksigner sign --ks <local-keystore> --ks-key-alias <alias> \
  --v1-signing-enabled true --v2-signing-enabled true \
  --out app-signed.apk app-aligned.apk
apksigner verify --verbose --print-certs app-signed.apk
zipalign -c -P 16 4 app-signed.apk
adb install -r app-signed.apk
```

Ключ подписи и пароль нельзя публиковать или хранить в репозитории.
Нельзя выполнять `jarsigner` после `zipalign` без повторной проверки
выравнивания, поскольку `jarsigner` может перепаковать ZIP.

## Если Android снова не устанавливает поверх старой версии

Не удалять старое приложение. Попробовать установку через системный
диспетчер файлов из каталога Download.

Чтобы установить реальную причину, нужны точный текст ошибки Android или
`adb install -r Smennik-0.8.0-install-fixed.apk`. Если появится
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`, на устройстве стоит APK,
подписанный другим сертификатом (например, ранняя debug-сборка). Тогда
обычное обновление с сохранением данных без соответствующего ключа
невозможно. Перед удалением приложения нужно экспортировать JSON-копию,
сохранить её вне приложения и только затем устанавливать новый APK с
импортом копии. Не предлагать удаление как первый способ.
