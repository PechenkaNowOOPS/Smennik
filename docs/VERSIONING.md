# Нумерация версий «Сменника»

## Единая система нумерации

Версия Android-приложения теперь задаётся **один раз** в корневом файле
[`version.properties`](../version.properties).

- `versionName` — читаемый номер по схеме **MAJOR.MINOR.PATCH**, например `0.1.6`.
- `versionCode` — целое число сборки Android, **строго больше, чем в предыдущем устанавливаемом APK**.

Номер версии автоматически считывается Gradle, отображается в нижней части
главного экрана («Версия 0.9.0 · сборка 17») и используется в названии
артефакта CI `Smennik-0.9.0-signed`. GitHub Actions сверяет формат номера
с первой записью `CHANGELOG.md`.

## Когда какой номер менять

| Изменение | Пример |
|---|---|
| Исправили дефект | `0.1.5` → `0.1.6` |
| Добавили крупную совместимую функциональность | `0.1.5` → `0.2.0` |
| Первый стабильный выпуск | `0.9.0` → `1.0.0` |
| Следующее совместимое расширение после стабильного релиза | `1.0.0` → `1.1.0` |
| Ломающие совместимость изменения после стабильного релиза | `1.x.y` → `2.0.0` |

При **каждом выпуске нового устанавливаемого APK** одновременно:
1. Измените `versionName` в `version.properties`.
2. Увеличьте `versionCode` минимум на единицу. Нельзя использовать прежний
   код сборки для новой версии, устанавливаемой поверх предыдущей.
3. Добавьте новую запись в самое начало `CHANGELOG.md`.
4. Запустите `python3 scripts/check_version.py` и GitHub Actions.

Следует отличать совместимость **версий** от совместимости **подписи**:
повышение `versionCode` само по себе не исправит несовпадение сертификатов.
Для обновлений поверх установленного приложения нужен одинаковый
`applicationId` и один постоянный ключ подписи — см. [SIGNING.md](SIGNING.md).

## Безопасность данных

Нумерация не меняет SQLite-данные и резервные копии. При любых изменениях
схемы БД требуется явная миграция. Перед первой заменой debug-сборки
на релиз с постоянной подписью экспортируйте JSON-резервную копию.
