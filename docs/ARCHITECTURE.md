# Архитектура: предварительное решение

**Статус:** проектирование. Исходный код приложения ещё не создан.

## Принципы

1. Offline-first: локальная база — источник истины для неавторизованного пользователя.
2. Чёткое разделение UI, бизнес-логики и хранилища.
3. Функции графика и финансов должны быть доступны для модульного тестирования без Android UI.
4. Внешняя синхронизация — опциональна; отсутствие сети не блокирует работу.
5. Данные не теряются при обновлении: миграции и экспорт.

## Предлагаемые модули Android

```text
app/                     # входная точка, навигация, DI
core/model/              # модели рабочего дня, смены, оплаты, выплаты
core/database/           # Room, DAO, миграции
core/preferences/        # DataStore
core/scheduling/         # вычисление повторяющихся графиков
feature/dashboard/       # главный экран
feature/calendar/        # календарь и редактор смен
feature/finance/         # расчёт зарплаты и история выплат
feature/analytics/       # аналитика
feature/settings/        # настройки и экспорт
```

Это **проектируемая** структура каталогов, не список реально существующих модулей.

## Сущности предметной области

- `ShiftTemplate`: начало/окончание, особенности смены.
- `WorkPattern`: продолжительность цикла и рабочие позиции в нём.
- `ShiftOccurrence`: уникальный экземпляр смены и его время.
- `ShiftOverride`: индивидуальное изменение дня или смены.
- `TimeEntry`: фактическое время, перерывы, источник фиксации.
- `PayRule`: ставка, валюта, период действия.
- `Payment`: реальная выплата и дата.

## Риски и проверки

- Ночные смены и переход между месяцами.
- Переход на летнее/зимнее время: хранить временные метки с зоной и однозначными правилами.
- Сдвиг даты начала графика, ручные исключения, смена шаблона.
- Восстановление после принудительного завершения Android-приложения.
- Округление денежных величин и ставки с разными периодами действия.
- Приватность при будущей Telegram-синхронизации.
