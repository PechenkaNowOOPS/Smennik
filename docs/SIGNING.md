# Постоянная подпись APK «Сменника»

Начиная с версии **0.1.4** релизные APK подписываются одним постоянным приватным ключом.
Публичный GitHub-репозиторий **не содержит** файл ключа и пароль.

## Почему это необходимо

Android устанавливает новую версию поверх старой только при совпадении
`applicationId` (сейчас `ru.smennik.app`), сертификата подписи и допустимом
`versionCode` (новая версия должна быть выше уже установленной).

В прежних debug-сборках GitHub Actions создавал временный ключ подписи на каждом
новом runner. Приватный ключ прошлой сборки не сохранён. Извлечь его из APK
невозможно. Поэтому **обновление поверх уже установленной 0.1.3 без
переустановки нельзя гарантировать**. Перед однократным переходом на новую
подпись экспортируйте JSON-копию смен в старом приложении и восстановите её
после установки нового подписанного APK.

## Однократная настройка GitHub Actions

Ключ создан отдельно от репозитория и передаётся владельцу проекта в приватном
архиве **Smennik-Private-Signing-Kit.zip**. Архив содержит:
- `smennik-stable.jks` — приватный ключ Android (alias: `smennik`);
- `signing-password.txt` — пароль хранилища и ключа;
- `signing-keystore-base64.txt` — значение первого GitHub Actions Secret;
- `Set-SmennikSigning.ps1` — Windows-скрипт установки через GitHub CLI;
- `INSTALL-SIGNING.txt` — инструкция.

Архив **никогда не загружать в открытый GitHub**, не публиковать содержимое,
не отправлять в чат. Хранить защищённую резервную копию комплекта отдельно.

В Settings → Secrets and variables → Actions добавьте два repository secrets:

| Имя секрета | Значение |
| --- | --- |
| `SMENNIK_KEYSTORE_BASE64` | Полная строка `signing-keystore-base64.txt` |
| `SMENNIK_KEYSTORE_PASSWORD` | Строка `signing-password.txt` |

Или на Windows: `gh auth login`, затем `Set-SmennikSigning.ps1` из
распакованного приватного комплекта.

После настройки откройте Actions → **Android Stable APK** → Run workflow.
Этот workflow запускается **вручную**, чтобы не помечать каждый push в `main`
как ошибочный из-за отсутствующих секретов. Автоматические тесты и неподписанная
сборка выполняются отдельно в **Build Unsigned APK for Offline Signing**.
Проверенный подписанный APK появляется в Artifacts под именем
`Smennik-<версия>-signed` только после успешного выполнения всех проверок.
Пока оба секрета не настроены, подписанный APK в CI получить невозможно.

## Защита от случайной смены ключа

- Сборка требует настроенных секретов и **прерывается** без них.
- CI больше не публикует временно подписанный debug APK как релиз.
- CI выполняет `apksigner verify` и сверяет сертификат SHA-256:
  `3396473C1CCD3A0C6EE483E098D1546BC759A2E92D01519F46930EEDB4614B6F`.
- При несовпадении подписи публикация APK отменяется.
- Проверка подписи — не замена испытанию установки и сохранения данных на телефоне.

**Важно:** файл JSON-копии содержит рабочие данные и не шифруется.
Переносите его только через доверенное хранилище.

## Важное замечание для выпусков 0.8.1 и новее

При локальном формировании комбинированной подписи **сначала JAR/v1**, затем
**ZIP-выравнивание** (для несжатых нативных `.so` минимум 16384, для
`resources.arsc` 4 байта), затем **APK Signature Scheme v2**. Не следует
подписывать v1 после v2, и нельзя перепаковывать уже v2-подписанный APK —
иначе подпись v2 становится невалидной.

Перед публикацией проверять v1, v2, сертификат, versionCode, applicationId,
выравнивание и CRC. Автоматический workflow публикует **только неподписанный** артефакт с
пометкой `DO-NOT-INSTALL`. Отдельный ручной workflow при наличии GitHub Secrets
собирает и проверяет подписанный APK (v1+v2, сертификат, выравнивание и данные
манифеста). Локальные ключи и пароли ни в коем случае не публикуются.
