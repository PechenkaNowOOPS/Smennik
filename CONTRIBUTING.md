# Порядок разработки

- `main` — состояние проекта, пригодное для восстановления.
- Работа над отдельными функциями — в ветках `feature/*`; исправления — в `fix/*`.
- Каждое изменение: цель, изменённые файлы, ручная/автоматическая проверка, риски.
- Значимые решения фиксировать в `docs/`.
- Не коммитить `.env`, ключи и сертификаты подписи, токены бота или реальные данные о зарплате.
- Для изменений схемы данных создавать миграции и регрессионные тесты.
- Для релиза подготовить версию, CHANGELOG, проверенный APK и отчёт о проверках.
